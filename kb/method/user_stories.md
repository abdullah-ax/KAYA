# User stories

## Format

As a [specific person], I want [goal], so that [reason].

Acceptance criteria: Given [situation], when [action], then [result].

## INVEST check

- **Independent:** can be built on its own.
- **Negotiable:** a starting point for a talk, not a contract.
- **Valuable:** a user gets something from it.
- **Estimable:** the team can guess the size.
- **Small:** fits in a short build cycle.
- **Testable:** acceptance criteria make it clear when it's done.

Slice stories top to bottom (one complete feature through every layer), not one layer at a time.

Sources: [Smartsheet](https://www.smartsheet.com/writing-user-story), [Visual Paradigm guide](https://s.visual-paradigm.com/guide/how-to-write-good-user-stories-examples-and-best-practices-for-story-writing/), [3Pillar on slicing](https://3pillarglobal.com/?p=23088).

## How agents use this

- The founder writes the stories. The co-founder asks questions until each one passes INVEST.
- Each story links to an interview note or is marked `ASSUMPTION`.
- The builder writes one test per acceptance criterion.
